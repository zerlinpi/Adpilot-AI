## 4. Entities with NO PostgreSQL columnDefinition literals

These four use plain `@Column(name=...)` with `UUID`/`String` Java types and no
explicit `columnDefinition`, so Hibernate maps them via dialect defaults. No
entity edit needed for task 3.1, but their tables still appear in the schema:

- inventory/entity/InventoryForecastEntity.java → `inventory_forecasts`
- inventory/entity/InventorySnapshotEntity.java → `inventory_snapshots`
- inventory/entity/ReplenishmentPlanEntity.java → `replenishment_plans`
- profit/entity/ProductProfitDailyEntity.java → `product_profit_daily`

> These entities declare `UUID` PK/FK fields without `columnDefinition`. Under
> `MySQLDialect`, Hibernate maps a bare `UUID` field differently than a
> `char(36)` column. Task 2.6 should verify the migration's id/FK column type
> for these four tables matches what Hibernate `validate` expects (consider
> adding explicit `columnDefinition = "char(36)"` if validation fails).
